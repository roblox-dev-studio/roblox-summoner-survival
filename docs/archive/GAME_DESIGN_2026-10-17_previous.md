# 소환사 서바이벌 상세 기획서

> 작업명: Summoner Survival / 소환사 서바이벌<br>
> 개발 팀: roblox-dev-studio<br>
> 작성일: 2026-10-17 · 초안 v0.1<br>
> 기준: 현재 저장소의 프로토타입. 이 문서의 제안은 아직 구현되거나 사용자에게 최종 확정된 사항이 아니다.

## 1. 게임을 한 문장으로

**플레이어가 직접 움직여 적의 포위를 피하고, 자동으로 싸우는 마법과 독립적인 소환수를 성장시키며 살아남는 1~4인 협동 생존 게임.**

플레이어가 지켜야 할 것은 자신의 캐릭터와 함께 싸우는 동료다. 고정 거점이나 방어 대상은 기본 모드에 두지 않는다. 기본 공격은 자동이지만 이동, 대시, 화염 파동의 방향과 사용 시점, 성장 선택은 플레이어가 결정한다.

핵심 장면은 다음과 같다.

“적들이 모인 곳에 골렘이 스스로 접근해 땅을 찍고, 플레이어는 그 틈으로 대시한다. 공중 마법진에서 얼음창이 나가 앞의 적을 밀어내고, 낙뢰가 바닥을 타고 퍼진다. 경험치를 모아 다음 능력을 선택하니 전투 방식이 달라진다.”

## 2. 합의된 방향과 이번 초안의 제안

### 2.1 지금까지의 대화에서 정한 방향

- 플레이어가 직접 이동하고 자신의 생존을 책임진다.
- 경험치를 채우면 선택지가 나오며 새 마법 습득, 기존 마법 강화, 소환수 강화를 고른다.
- 소환수는 플레이어에게 붙어 다니는 장식이 아니라 독립적으로 적을 찾아 움직인다.
- 골렘의 대지 강타는 적이 모인 곳에 자동으로 사용한다.
- 플레이어는 자신의 공격과 회피에 집중한다.
- 혼자서도, 친구들과도 플레이할 수 있도록 한다.
- 마법은 명확하게 식별되어야 한다. 얼음창은 뾰족한 결정, 번개는 낙뢰와 지면 전류, 화염은 실제 불꽃의 형태를 가진다.
- 골렘 외에 드래곤이나 재미있는 소환수로 확장할 여지를 둔다.

### 2.2 이 문서에서 새로 제안하는 기본안

| 항목 | 제안 | 이유 |
| --- | --- | --- |
| 인원 | 1~4인 | 친구끼리 모이기 쉽고 화면과 적 수를 관리할 수 있음 |
| 다음 완성 목표 | 현재 3분 모드를 먼저 완성 | 콘텐츠 확장 전에 기본 재미와 협동을 검증 |
| 이후 기본 모드 | 최대 6분, 후반 보스 전투 | 성장 조합을 경험할 시간과 명확한 마지막 목표 확보 |
| 공격 구성 | 자동 마법 3종 + 수동 공격 1종 + 대시 | 조작 부담을 늘리지 않고 선택할 여지를 확보 |
| 소환수 | 첫 버전은 1인당 골렘 1기 | 여러 소환수의 AI·충돌·화면 혼잡을 먼저 제한 |
| 경험치 | 팀 공유, 선택은 개인별 | 막타와 수집 경쟁을 없애고 각자의 빌드 유지 |
| 장기 성장 | 새 선택지와 외형 해금 중심 | 오래 한 사람과 처음 온 친구가 함께 플레이하기 쉽게 함 |
| 사망 | 솔로는 패배, 협동은 쓰러짐과 구조 | 친구를 도울 이유를 만들고 관전 대기를 줄임 |

이 기본안은 구현을 시작할 수 있게 선택한 초안이다. 플레이 검증 결과에 따라 바꾸며, 숫자는 확정 밸런스가 아니다.

## 3. 플레이어가 느껴야 할 재미

### 3.1 피해서 살아남는 재미

항상 공격 버튼을 누르지 않아도 적의 밀도, 위험 표시, 경험치 위치를 보며 움직일 이유가 있어야 한다. 대시는 이동 단축 수단이면서 포위에서 빠져나오는 중요한 자원이다.

오래 살아남는 방법이 단순히 원을 그리며 달리는 것 하나로 고정되면 안 된다. 돌진 적, 예고되는 원거리 공격, 짧은 지역 위험을 조합해 이동 방향을 가끔 바꾸게 만든다.

### 3.2 소환수와 호흡을 맞추는 재미

골렘이 강타를 준비하면 플레이어는 적을 그쪽으로 유도하거나, 골렘이 열어준 길로 이동한다. 조작하지 않아도 행동이 읽히고 도움이 된다고 느끼는 것이 중요하다.

골렘이 영리하다는 인상은 복잡한 AI보다 다음 세 가지에서 나온다.

1. 죽은 적을 계속 쫓지 않는다.
2. 많은 적이 있는 곳과 주인 가까운 위험을 구분한다.
3. 너무 멀리 가면 돌아오고, 공격 기회를 계속 놓치지 않는다.

### 3.3 선택 때문에 전투가 바뀌는 재미

매번 피해량만 증가시키지 않는다. 관통, 연쇄 수, 밀치기, 강타 범위처럼 전투 장면이 달라지는 선택을 섞는다. 단, 첫 버전에 모든 강화에 새로운 규칙을 붙이지는 않는다.

### 3.4 친구와 함께 해결하는 재미

경험치는 함께 얻고, 위기에 빠진 친구를 제압 마법이나 화염 파동으로 도와준다. 특정 직업이나 필수 조합이 없어도 누구나 혼자 시작할 수 있어야 한다.

## 4. 현재 구현 상태와 차이

| 영역 | 현재 구현 | 부족하거나 바꿀 부분 |
| --- | --- | --- |
| 라운드 | 180초 생존, 승패와 재시작 | 로비, 준비, 협동 종료 규칙 |
| 플레이어 | 이동, 자유 카메라, 체력 100 | 피격 표현, 모바일 검증, 입력 충돌 |
| 수동 기술 | Q 화염 파동, E 대시 | 모바일 방향 보조와 입력 안내 |
| 성장 | 레벨업 3지선다, 능력 5단계 | 선택지 편중, 수치 비교, 빌드 분기 |
| 자동 마법 | 화염탄·연쇄 번개·빙결 얼음창 | 역할별 대상 선택, 고단계 차별화 |
| 골렘 | 독립 이동, 밀집 적 자동 강타 | 벽·경로 막힘, 과도한 밀치기와 추격 조정 |
| 적 | 동일한 추적형 적 | 속도형·원거리형·정예, 공격 예고 |
| 협동 | 여러 플레이어 상태와 경험치 공유 기반 | 실제 다중 클라이언트 검증, 구조, 이탈 처리 |
| 효과 | 불꽃·낙뢰·빙결·강타 | 아군 효과 투명도, 기기별 효과 수 제한 |
| 저장 | 없음 | 설정과 해금 저장, 오류 복구 |
| 배포 | GitHub 소스와 Studio 설치기 | Roblox 플레이 공개, 버전 관리 |

현재 골렘은 효과 확인을 위해 `PREVIEW_MAX_GOLEM_EFFECTS = true`다. 단계 1에서도 단계 5의 외형을 보여주므로 정식 플레이 검증 전에 끈다. 실제 피해 범위와 보이는 범위가 다르면 회피와 강화 판단을 오해할 수 있다.

현재 자동 화염탄은 피해를 먼저 적용하고 시각 탄환이 뒤에 도착한다. 이후에는 탄환 도착과 피해를 맞추거나, 즉시 적중하는 마법이라는 연출로 통일한다. 얼음창처럼 실제 이동하는 기술은 도착 판정을 유지한다.

## 5. 범위: 무엇부터 완성할 것인가

### 5.1 단계 A — 공유 가능한 3분 버전

목표는 친구가 설명 없이 한 판을 끝내고 “한 번 더 하자”라고 말할 정도의 완성도다.

- 기존 전장 1개, 골렘 1종, 자동 마법 3종, 화염 파동, 대시.
- 추적형·속도형·원거리형 적 3종.
- 한 종류의 정예 적과 마지막 45초의 작은 전투 변화.
- 1~4인 입장, 공유 경험치, 협동 레벨업, 쓰러진 동료 구조.
- 읽기 쉬운 UI, 효과 강도 설정, 결과 화면.
- 기본 안내와 실제 2~4인 검증.

이 단계에서는 보스, 드래곤, 합성, 장비, 거래, 재화 상점, 배틀패스, 여러 맵을 추가하지 않는다.

### 5.2 단계 B — 반복 플레이할 5~6분 버전

- 전반 생존, 중반 정예와 맵 사건, 후반 보스.
- 골렘과 드래곤 중 시작 소환수 선택.
- 빌드의 역할 차이가 드러나는 강화와 소수의 조합 효과.
- 해금 과제, 기록, 설정 저장.
- 첫 방문 안내와 친구 파티 흐름 개선.

### 5.3 단계 C — 운영하며 확장

- 맵·보스·소환수 추가, 도전 난이도, 주간 조건.
- 독자적인 유머 소환수, 외형과 감정 표현.
- 실제 유지율과 성능을 확인한 뒤 수익화 검토.

단계 A의 재미나 협동이 부족하면 단계 B의 콘텐츠를 늘리기보다 A를 고친다.

## 6. 한 판의 흐름

### 6.1 입장과 준비

초기에는 서버 하나를 한 파티의 전장으로 사용한다. 로비와 전장을 별도 장소로 나누는 구성은 이후로 미룬다.

1. 입장하면 준비 공간에서 조작 안내와 참여자 목록을 본다.
2. 솔로는 바로 시작할 수 있다.
3. 협동은 준비 완료를 누르고, 참가자 전원이 준비되면 5초 뒤 시작한다.
4. 최대 인원은 4명이다. 진행 중 들어온 사람은 다음 판 대기와 관전을 선택한다.
5. 중간 참가 때문에 이미 진행 중인 난이도나 경험치를 바꾸지 않는다.

방장은 처음 시작한 사람이다. 방장이 나가면 남은 사람 중 먼저 입장한 사람에게 넘긴다. 전투 중 방장의 연결 상태가 라운드 진행을 좌우하지 않게 한다.

### 6.2 3분 모드의 시간 구성

| 시간 | 전투 구성 | 플레이어에게 줄 경험 |
| --- | --- | --- |
| 0:00~0:20 | 추적형 적 소수, 첫 경험치 | 이동과 자동 공격 이해 |
| 0:20~0:50 | 첫 성장 선택, 적 수 완만히 증가 | 내가 능력을 바꿀 수 있음을 확인 |
| 0:50~1:20 | 속도형 적을 소량 섞음 | 대시와 전방 파동 사용 |
| 1:20~2:00 | 원거리형 적 등장, 첫 정예 | 위험 표시를 보고 경로 선택 |
| 2:00~2:30 | 서로 다른 적 조합 | 빌드의 강점과 약점 경험 |
| 2:30~3:00 | 마지막 압박, 새 적 유형 추가 금지 | 배운 능력으로 버티는 마무리 |
| 3:00 | 생존자 승리, 파티 결과 | 성장 결과 확인과 재도전 |

시간표는 적을 한꺼번에 소환하는 고정 웨이브가 아니라 출현 비율과 압박을 바꾸는 기준이다. 처음 보는 적을 마지막 순간에 설명 없이 넣지 않는다.

### 6.3 이후 보스 모드

최대 6분을 기준으로 5:00에 보스가 등장한다. 보스를 처치하면 즉시 승리하고, 6:00까지 처치하지 못하면 시간 초과 패배한다. 일반 적 생성은 줄이고 보스 공격을 읽는 데 집중시킨다.

따라서 단계 B의 승리 조건은 “5분까지 생존한 뒤 제한 시간 내 보스 처치”다. 단계 A의 “3분 생존”과 UI·설명에서 구분한다. 보스 모드를 아직 구현하지 않았는데 6분 타이머만 늘리지는 않는다.

### 6.4 결과와 재도전

- 결과에 승패, 생존 시간, 도달 레벨, 사용한 마법과 소환수, 최고 강화 단계를 보여준다.
- 협동은 개인 처치 수 순위보다 구조 횟수, 정예 처치, 팀 생존 결과를 먼저 보여준다.
- “다시 도전”과 “준비 공간으로”를 제공한다.
- 협동은 한 사람이 다시 도전을 눌러 다른 사람의 진행을 초기화하지 못한다. 전원 라운드 종료 후 재도전 투표를 진행하며 준비하지 않은 사람은 대기로 남을 수 있다.

## 7. 조작·카메라·회피

### 7.1 공통 원칙

이동이 주 조작이다. 초보자는 자동 공격만으로 시작할 수 있고, 익숙해지면 화염 파동과 대시로 더 오래 살아남는다. 수동 기술은 첫 버전에서 두 개를 넘기지 않는다.

| 기능 | PC | 모바일 제안 |
| --- | --- | --- |
| 이동 | WASD | 기본 이동 스틱 |
| 카메라 | 우클릭 회전, 휠 확대·축소 | 기본 터치 회전과 확대·축소 |
| 화염 파동 | Q / 화면 버튼 | 큰 전용 버튼, 누르면 발사 |
| 대시 | E / 화면 버튼 | 이동 스틱 방향으로 대시 |
| 성장 선택 | 카드 클릭 | 카드 터치 |

모바일 파동 방향은 이동 중에는 이동 방향, 정지 시에는 사거리 안의 위험한 적 방향으로 보정하는 안을 시험한다. PC는 캐릭터가 바라보는 방향을 기본으로 유지한다. 다른 입력 장치에서는 마지막 이동 방향을 저장해 정지 상태의 대시를 예측할 수 있게 한다.

### 7.2 대시

현재 기준은 약 15스터드 이동, 0.23초 지속, 3초 재사용 대기시간, 약 0.28초 보호다. 보호가 적용되는 피해 유형을 통일해 설명한다. 지금은 접촉 피해 보호가 구현되어 있으므로 새 원거리 공격에도 동일한 규칙을 적용할지 결정한 뒤 확장한다.

벽을 통과하지 않으며 전장 밖으로 빠져나갈 수 없다. 대시 종료 후 이동 속도와 회전 상태가 반드시 복구되어야 한다. 레벨업, 쓰러짐, 라운드 종료가 대시 도중 발생해도 같은 복구 규칙을 적용한다.

### 7.3 피격

같은 적이 겹쳤다고 한 프레임에 수십 번 피해를 주지 않는다. 개별 적 공격 간격에 더해 플레이어에게 짧은 공통 피격 보호를 두는 안을 검증한다. 제안 시작값은 0.35초이며, 대시 보호와 단순 합산하지 않는다.

공격받으면 짧은 캐릭터 섬광, 체력 감소, 작은 방향 표시를 보여준다. 화면 흔들림과 붉은 화면 효과는 끌 수 있다. 기본 설정에서 화면 전체를 반복적으로 가리지 않는다.

## 8. 마법과 빌드 구성

### 8.1 슬롯과 시작 상태

단계 A는 지금처럼 화염탄 1단계와 골렘 1단계로 시작한다. 번개와 얼음창은 성장 선택으로 배운다. 자동 마법 3개를 모두 익힐 수 있지만 한 판에서 모두 최대로 만들 필요는 없다.

단계 B부터 자동 마법 슬롯을 3개로 제한하고 소환수 슬롯 1개를 별도로 둔다. 새 마법을 더 추가하더라도 자동 공격이 끝없이 늘지 않게 한다. 수동 화염 파동과 대시는 슬롯을 차지하지 않는다.

초기에는 능력 교체 메뉴를 만들지 않는다. 슬롯이 찼으면 새 마법 습득 카드는 나오지 않는다. 선택 전에 남은 슬롯을 명확히 표시한다.

### 8.2 역할 구분

| 능력 | 주 역할 | 강한 상황 | 약한 상황 |
| --- | --- | --- | --- |
| 화염탄 | 꾸준한 작은 범위 피해 | 가까이 붙은 보통 적 | 멀리 흩어진 적 |
| 화염 파동 | 직접 길을 여는 전방 공격 | 포위에서 탈출, 구조할 공간 확보 | 뒤에서 오는 적, 재사용 대기 중 |
| 연쇄 번개 | 흩어진 여러 적 연결 | 여러 방향의 적, 속도형 적 | 혼자 남은 단일 강적 |

모든 기술에 같은 관통·폭발·빙결을 붙이지 않는다. 역할이 섞일수록 선택의 의미가 줄어든다.

아래는 소스에서 확인한 현재 값이다. 단일 대상에 계속 적중한다는 보장이 없으므로 표의 수치를 실제 전투 성능으로 단정하지 않는다.

골렘 고단계는 파편의 중복 적중과 두 번 타격까지 포함하면 상승폭이 크다. 다른 강화와 같은 “한 단계”로 비교해 과도하게 유리하지 않은지 확인한다.

### 8.4 단계별 성장의 제안

첫 버전에서는 현재 수치 상승과 3·5단계의 중요한 변화를 정리한다. 다음 표의 기능 변화는 새 제안이다.

| 능력 | 1단계 | 2단계 | 3단계의 변화 | 4단계 | 5단계의 완성 |
| --- | --- | --- | --- | --- | --- |
| 화염탄 | 자동 화염탄 | 피해 상승 | 폭발이 더 잘 보이고 범위 증가 | 발사 간격 감소 | 작은 잔불 구역 또는 추가 탄환 중 하나를 택해 검증 |

“중 하나를 검증”은 동시에 구현하라는 뜻이 아니다. 화면 식별과 성능을 비교해 하나를 고른다. 단계 A에서는 새 관통·잔불 구현보다 기존 능력의 균형과 피드백을 먼저 완성한다.

## 9. 레벨업과 선택지 설계

### 9.1 경험치

누가 마지막 피해를 줬는지와 관계없이 적이 경험치를 떨어뜨리고, 한 명이 수집하면 참여 플레이어가 같은 양을 받는다. 수집 담당이 손해를 보거나 팀원이 경험치를 뺏는 느낌을 주지 않는다.

쓰러져 구조를 기다리는 사람도 경험치를 받는다. 연결이 끊겨 참가 상태가 종료된 사람이나 이번 판 관전자에게는 전투 경험치를 지급하지 않는다. 수집 한 번에 중복 지급되지 않도록 서버가 처리한다.

현재 경험치 구슬이 180개에 도달하면 새 구슬이 생성되지 않는다. 정식 버전에서는 가까운 구슬을 합쳐 같은 경험치 총량을 보존한다. 성능 제한 때문에 획득 가능한 경험치를 없애지 않는다.

### 9.2 성장 속도 목표

- 첫 선택은 첫 적을 만난 뒤 약 20~30초 안에 경험하도록 조정한다.
- 3분 모드의 목표 성장량은 대략 7~10번 선택이다.
- 5~6분 모드의 목표 성장량은 대략 14~18번 선택이다.
- 이는 검증할 가설이다. 현재 공식만으로 이 횟수가 보장된다는 뜻은 아니다.

현재 필요 경험치는 `5 + (레벨 - 1) × 3`이다. 협동에서는 적이 늘어 공유 경험치 유입도 늘기 때문에 적 체력만 늘려서는 성장 속도가 맞지 않는다. 인원별 경험치 획득량과 실제 선택 횟수를 함께 측정한다.

### 9.3 카드 생성 규칙 제안

매번 서로 다른 3장을 제시한다. 잠긴 능력, 이미 최고 단계인 능력, 슬롯 조건에 맞지 않는 능력은 제외한다.

1. 강화할 수 있는 보유 능력이 있으면 최소 1장을 보유 능력 강화로 구성한다.
2. 비어 있는 슬롯이 있고 아직 배우지 않은 능력이 있으면 초반 선택에서 새 능력을 주기적으로 보장한다.
3. 방어·이동·수집 카드는 초반부터 후보에 포함한다. 지금처럼 마법 후보가 부족할 때만 등장시키지 않는다.
4. 같은 세 카드 조합이 계속 반복되면 후보를 다시 구성한다.
5. 운이 나빠 공격 능력을 전혀 성장시키지 못하는 판이 생기지 않게 한다.

첫 버전은 확률 등급, 희귀도, 유료 다시 뽑기를 넣지 않는다. 선택지를 읽고 비교하는 재미부터 검증한다.

### 9.4 카드 표시

각 카드에는 이름, 현재 단계 → 다음 단계, 한 줄 효과, 역할 아이콘을 넣는다. 예를 들어 “빙결 얼음창 2 → 3 / 첫 적을 뚫고 뒤의 적까지 공격”처럼 선택 결과를 구체적으로 보여준다.

피해량 수치만 길게 쓰기보다 주요 변화를 먼저 표시하고, 세부 수치는 펼쳐 볼 수 있게 한다. 최고 단계에는 “완성” 표시를 사용한다.

### 9.5 솔로와 협동의 선택 시간

솔로는 기존처럼 전투를 멈추고 제한 시간 없이 선택한다.

협동은 공유 경험치로 동시에 선택 시점을 맞추고, **모든 참가자에게 최대 8초의 공통 선택 시간을 제공하며 전투 시뮬레이션을 정지하는 안**부터 시험한다. UI와 선택 제한 시간은 실제 시간으로 진행한다. 전원이 선택하면 즉시 전투를 재개한다.

- 선택 중 공격·쿨다운·빙결·대시·라운드 시간·부활 진행도 함께 정지한다.
- 선택을 안 한 사람은 8초 뒤 자동 선택한다.
- 자동 선택 우선순위는 보유 공격 능력 강화 → 새 공격 능력 → 생존 강화로 고정하고 UI에 알린다.
- 연속 레벨업이 발생하면 최대 2회까지만 연속 선택 창을 열고 나머지는 다음 전투 구간으로 넘긴다.
- 정지 빈도가 지나치면 선택 보상을 모아 약 30초 간격의 공동 선택 구간으로 바꾸는 안을 비교한다.

현재는 협동 선택 중 해당 플레이어가 이동·공격을 멈추지만 접촉 피해는 받지 않는 구조다. 무기한 보호 상태가 생길 수 있으므로 그대로 출시하지 않는다.

솔로 여부는 **이번 판의 시작 참가 인원**으로 판정한다. 협동에서 한 명만 살아 있다고 갑자기 무제한 솔로 정지 규칙으로 전환하지 않는다.

## 10. 소환수 상세 설계

### 10.1 골렘의 역할

첫 버전에서 골렘은 체력 없이 계속 활동하는 제압 소환수다. 적의 주 타깃은 플레이어다. 따라서 골렘을 “피해를 대신 받아주는 탱커”로 설명하지 않고 “적 무리를 흩뜨리고 길을 열어주는 동료”로 설명한다.

골렘 체력, 치료, 재소환 재화는 이후에 필요성이 확인될 때 검토한다. 소환수 관리 때문에 플레이어가 회피와 성장에 집중하지 못하는 상황을 피한다.

### 10.2 행동 우선순위

| 우선순위 | 행동 | 조건 |
| --- | --- | --- |
| 1 | 복귀 | 주인과 너무 멀어지거나 이동 불능 |
| 2 | 진행 중 공격 마무리 | 유효한 공격 동작 중이며 긴급 복귀 상황이 아님 |
| 3 | 주인 주변 밀집 적 강타 | 주인 가까이에 위험한 무리가 있고 강타 사용 가능 |
| 4 | 일반 밀집 적 강타 | 접근 가능한 곳에 3마리 이상 모임 |
| 5 | 가까운 적 기본 공격 | 강타할 무리가 없고 추적할 적이 있음 |
| 6 | 주변 순찰 | 적이 없음 |

타깃은 매 프레임 바꾸지 않는다. 현재 타깃이 죽었거나 멀어졌거나, 명확히 더 위험한 무리가 나타났을 때 갱신한다. 경로가 막힌 목표는 일정 시간 후 포기한다.

### 10.3 강타의 실행과 헛공격

목표 지점에 도착한 뒤 준비 동작을 시작한다. 준비 중 목표가 흩어지면 짧은 범위 안에서 한 번 방향을 보정하되, 골렘이 회전하면서 순간 이동한 것처럼 보이지 않게 한다.

공격 직전의 마지막 순간에는 타격 지점을 고정한다. 땅을 찍는 위치에서 피해와 효과가 동시에 발생한다. 준비가 시작되자마자 피해를 주지 않는다.

밀치기는 주인이 도망갈 길을 만들어야 한다. 적을 너무 멀리 던져 골렘이 끝없이 추격하거나 다른 마법의 사거리 밖으로 보내면 거리와 속도를 줄인다.

### 10.4 여러 골렘이 같은 곳을 찍는 문제

협동에서 모든 골렘이 동일한 한 마리나 같은 무리만 고집하면 화면이 가려지고 다른 방향이 비게 된다. 가장 가까운 위협을 우선하되, 다른 골렘이 이미 강타를 준비 중인 무리는 평가 점수를 낮추는 간단한 예약 규칙을 제안한다.

이 규칙은 강제 역할 분담이 아니다. 다른 유효한 목표가 없으면 같은 곳을 공격할 수 있다. 보스에는 함께 공격할 수 있다.

### 10.5 드래곤 확장안

드래곤은 플레이어 근처 공중을 이동하고, 목표 방향으로 짧은 브레스를 뿜는다. 골렘과 달리 넓은 전방 공격과 지속 피해에 집중한다. 초기 드래곤에는 자유 비행 물리와 복잡한 지형 탐색을 넣지 않고 정해진 높이의 비행 경로를 사용한다.

골렘과 드래곤을 동시에 여러 기 소환하는 기능은 이후로 미룬다. 시작 소환수 선택으로 구현하면 같은 슬롯·강화 체계 안에서 두 종류의 재미를 비교할 수 있다.

### 10.6 유머·브레인롯 계열 소환수

특정 유행 캐릭터의 복제보다 직접 만든 익살스러운 소환수를 우선한다. 돌 굴리는 감자 기사, 과하게 진지한 작은 오리 마법사처럼 행동과 실루엣이 기억에 남는 방향을 시험할 수 있다.

이 종류의 소환수도 전투 역할이 있어야 한다. 웃기는 외형만 다르고 공격은 골렘과 똑같은 상태로 수를 늘리지 않는다. 외부 캐릭터나 소재를 도입하면 출처와 사용 조건을 확인하고 기록한다.

## 11. 적·정예·보스

### 11.1 첫 버전의 적 3종

| 적 | 행동 | 플레이어 대응 | 외형과 예고 |
| --- | --- | --- | --- |
| 그림자 보병 | 가까운 플레이어를 따라가 접촉 공격 | 무리 관리, 기본 이동 | 보라색 몸과 밝은 눈 |
| 질주 그림자 | 잠깐 멈춰 방향을 잡은 뒤 직선 돌진 | 옆으로 이동하거나 대시 | 가는 몸, 지면 직선 예고 |
| 잿빛 시전자 | 일정 거리 유지, 느린 탄환 발사 | 탄환 틈으로 이동, 원거리 적 우선 처리 | 둥근 지팡이 표식, 발사 준비 빛 |

속도형 적을 단순히 플레이어보다 빠르게 만들어 피할 수 없게 하지 않는다. 빠른 구간과 약한 구간을 나누며, 공격 전에 예고한다. 원거리형도 화면 밖에서 즉시 적중하는 탄환을 발사하지 않는다.

### 11.2 밀집과 이동

적이 모두 같은 위치에 겹치면 개체 수와 위협이 읽히지 않는다. 가까운 적끼리 약하게 분리하는 이동을 적용하고, 플레이어 바로 앞에서 대형 덩어리가 되지 않도록 조정한다.

첫 전장은 장애물이 적은 평지로 유지한다. 모든 적에게 복잡한 경로 탐색을 매 프레임 수행하는 구조로 시작하지 않는다. 막힘이 실제로 문제가 되는 구역에만 경로 보정을 사용한다.

### 11.3 정예

보통 적의 체력만 크게 올린 형태를 피한다. 크기·문양으로 알아볼 수 있고 다음 변형 중 하나만 붙인다.

- 느리지만 짧은 범위 충격파를 사용하는 무거운 적.
- 주위 보통 적을 잠깐 빠르게 하는 지휘형 적.
- 죽을 때 예고 후 작은 위험 지대를 남기는 적.

한 정예에 여러 특성을 무작위로 붙이는 시스템은 이후로 미룬다. 정예 처치 보상은 많은 경험치와 소량 회복으로 시작하며 새 재화는 만들지 않는다.

### 11.4 이후 첫 보스 제안: 균열의 수문장

원형 전장과 기존 돌·룬 분위기를 활용한다. 새로 제작할 모델과 애니메이션 수를 줄이면서 공격 판독성을 확보한다.

| 패턴 | 예고 | 대응 | 피해야 할 문제 |
| --- | --- | --- | --- |
| 전방 땅찍기 | 팔을 들고 부채꼴 표시 | 옆으로 이동 | 캐릭터 뒤까지 보이지 않는 피해 발생 |
| 돌진 | 직선 경로를 먼저 표시 | 경로 밖으로 이동 | 화면 밖에서 갑자기 출발 |
| 균열 고리 | 바닥에 고리와 안전 구역 표시 | 빈 공간으로 이동 | 전체 전장을 동시에 위험 구역으로 만들기 |
| 보통 적 소환 | 특정 가장자리 소환 표시 | 소수의 적을 정리하며 보스 대응 | 보스와 보통 적 효과가 함께 화면을 가림 |

체력이 낮아지면 이미 배운 패턴의 간격이나 조합을 바꾼다. 마지막에 처음 보는 즉사 공격을 추가하지 않는다. 단계 B에서는 패턴 2개로 시작해 공략 가능성을 검증한 뒤 늘린다.

### 11.5 상태 이상 저항

보통 적은 빙결과 밀치기가 정상 적용된다. 정예는 지속시간과 이동 거리를 줄이고, 보스는 밀치기에 움직이지 않되 얼음 공격의 효과를 별도 표시한다.

보스에게 제압 효과가 완전히 무의미해지지 않도록 짧은 공격 지연이나 점진적인 제압 게이지 중 하나를 나중에 검증한다. 첫 보스는 빙결 지속 감소부터 시작하며 복잡한 게이지를 필수로 넣지 않는다.

연속 빙결로 보스가 전혀 행동하지 못하는 상황은 제한한다. 적용 실패가 아니라 저항이라는 것을 작은 아이콘과 타격 효과로 알린다.

## 12. 난이도와 출현 규칙

### 12.1 압박을 만드는 네 가지 축

적 수, 적 체력, 빠른 적의 비율, 원거리 공격 빈도를 동시에 급격히 올리지 않는다. 구간마다 한두 가지를 바꿔 무엇이 어려워졌는지 읽히게 한다.

플레이어의 현재 강함에 맞춰 적 체력을 즉시 올리는 방식은 기본으로 사용하지 않는다. 좋은 선택을 해서 강해졌다는 보상이 남아야 한다.

### 12.2 출현 위치

- 전장 가장자리 또는 미리 정한 출현 지점에서 생성한다.
- 플레이어 바로 옆이나 몸 안에는 생성하지 않는다.
- 원거리형과 정예는 출현 표시 후 움직인다.
- 출현 공간이 부족하면 다른 지점을 찾거나 잠깐 늦춘다.
- 플레이어가 가장자리에 있다고 반대편에서만 적이 와 완전히 안전해지는지 확인한다.

### 12.3 인원 보정의 초기 가설

다음 수치는 튜닝 출발점이며 현재 코드의 공식이 아니다.

| 참가 인원 | 보통 적 출현량 배율 | 보통 적 체력 배율 | 정예·보스 체력 배율 |
| --- | --- | --- | --- |
| 1 | 1.00 | 1.00 | 1.00 |
| 2 | 1.35 | 1.10 | 1.75 |
| 3 | 1.65 | 1.20 | 2.45 |
| 4 | 1.90 | 1.30 | 3.10 |

네 명이라고 일반 적을 정확히 네 배로 만들면 화면·네트워크·경험치 획득 속도가 모두 크게 변한다. 적 수를 제한하고 필요한 압박을 공격 조합과 정예 체력으로 분산한다.

출현량이 늘면 공유 경험치도 늘어난다. 인원 보정은 체력·처치 시간·경험치 속도를 한 세트로 검증하고, 필요하면 적의 경험치 가치나 필요 경험치를 조정한다.

참가자 이탈 시 체력은 갑자기 비율로 회복하거나 깎지 않는다. 이후 출현량부터 천천히 보정하고, 이미 출현한 보스의 규칙은 판 시작 시 기준을 유지하는 안부터 시험한다.

## 13. 협동과 쓰러짐

### 13.1 기본 관계

아군 피해, 아군 밀치기, 경험치 경쟁은 없다. 플레이어와 아군 소환수는 서로 길을 막지 않는다. 적의 타깃은 가장 가까운 살아 있는 플레이어를 기본으로 하되 작은 거리 변화에 매 순간 바뀌지 않게 한다.

### 13.2 구조 규칙 제안

- 체력이 0이 되면 협동에서는 즉시 탈락하지 않고 쓰러진다.
- 쓰러진 사람은 공격·수집·적 타깃에서 제외되며 같은 판의 경험치는 계속 받는다.
- 쓰러진 동안 본인의 자동 마법과 소환수 공격도 멈춘다. 살아 있는 동료의 전투로 생긴 경험치는 공유받고, 공동 성장 선택에는 참여한다.
- 동료가 가까이서 구조 입력을 3초 유지하면 체력 30%로 일어난다.
- 구조자는 공격을 받거나 멀어지거나 입력을 놓으면 구조가 중단된다.
- 반복 구조의 시작 시간은 3초, 4초, 최대 5초로 늘어난다.
- 일어난 직후 2초 동안 피해를 받지 않으며 공격은 가능하다.
- 첫 협동 버전은 쓰러진 사람에게 별도 사망 제한 시간을 두지 않는다. 전원이 쓰러지면 즉시 팀 패배다.

무한 구조가 사실상 무적처럼 작동하면 먼저 구조 위치의 위험, 중단 규칙, 보호시간을 조정한다. 처음부터 부활 아이템과 결제 부활을 도입하지 않는다.

### 13.3 솔로 규칙

기본 모드는 체력 0이면 즉시 패배한다. 처음 방문한 사람을 위한 연습 모드에는 한 번의 자동 복귀를 제공할 수 있지만, 기본 모드와 기록을 구분한다.

### 13.4 협동 상태의 예외

| 상황 | 처리 제안 |
| --- | --- |
| 살아 있는 사람이 모두 나감 | 남은 쓰러진 참가자도 팀 패배로 정리 |
| 레벨업 중 한 명 이탈 | 남은 참가자의 선택만 기다리거나 제한 시간 종료 |
| 구조 도중 대상 이탈 | 구조를 중단하고 상태 제거 |
| 모두 동시에 쓰러짐 | 한 번만 패배 판정, 결과 중복 지급 방지 |
| 한 명이 연결 끊김 | 골렘·투사체 정리, 팀 상태 갱신 |
| 진행 중 재접속 | 첫 버전은 다음 판 대기, 중간 복구는 이후 구현 |
| 결과 화면에서 한 명만 재도전 | 진행 중인 다른 사람의 전장을 초기화하지 않음 |

## 14. 맵과 전장 사건

### 14.1 첫 전장

현재 원형 룬 전장을 유지한다. 중앙은 이동하기 편하고, 가장자리는 너무 좁거나 시야가 가려지지 않게 한다. 높이 차와 복잡한 장애물은 최소화한다.

외형 장식이 적의 공격 표시와 혼동되지 않도록 바닥의 밝은 룬은 낮은 대비로 유지한다. 경계 바깥을 갈 수 없어도 투명 벽에 갑자기 막힌 느낌이 들지 않게 돌과 바닥 표시로 경계를 보여준다.

### 14.2 계속 원만 도는 플레이 방지

정해진 시간에 다음 중 하나를 짧게 발생시키는 안을 시험한다.

- 전장 일부에 예고 후 균열이 생겨 다른 방향으로 이동하게 함.
- 짧은 시간만 남는 회복 꽃을 위험 지역 근처에 생성.
- 정예가 떨어뜨린 경험치 덩어리를 회수하기 위해 경로를 바꾸게 함.

단계 A에서는 회복 기회 하나와 원거리형 적 배치만으로도 경로 변화가 생기는지 먼저 확인한다. 사건을 동시에 여러 개 발생시키지 않는다.

### 14.3 회복

회복은 현재 레벨업 생존 카드에 크게 의존한다. 새 능력을 배우고 싶어서 회복을 포기하는 선택도 재미지만, 회복 카드가 나오지 않아 반드시 실패하는 상태는 피한다.

정예 처치 시 회복 조각을 떨어뜨리는 안부터 시작한다. 회복은 팀원 각자에게 적용되도록 설계하거나 획득자가 가장 체력이 낮은 아군도 일부 회복시키는 단일 규칙을 정한다. 첫 제안은 “획득 시 팀원 전원 최대 체력의 10% 회복, 살아 있는 참가자에게만 적용”이다.

최대 체력 증가 카드와 즉시 회복의 효과를 UI에서 분리해 보여준다. 회복량이 체력 최대치를 넘지 않도록 한다.

## 15. 효과·소리·화면 정보

### 15.1 형태가 기술을 설명해야 한다

| 요소 | 시각 언어 | 확인할 기준 |
| --- | --- | --- |
| 화염 | 노란 중심, 주황·붉은 불꽃, 위로 솟는 불씨 | 판이나 직육면체가 아닌 불길로 식별 |
| 번개 | 위에서 아래로 내려오는 흰 중심과 청색 빛, 바닥 분기 | 낙뢰 시작점과 실제 타격 지점이 일치 |
| 얼음 | 세로 공중 마법진, 뾰족한 다면체 창날, 서리 | 네모 덩어리처럼 보이지 않고 진행 방향이 읽힘 |
| 골렘 | 팔 준비, 지면 충격, 바위와 둥근 파동 | 손이 닿는 순간 피해, 보이는 범위와 실제 범위 일치 |
| 적 공격 | 모양과 채움으로 구분된 바닥 예고 | 아군 효과가 겹쳐도 위험 구역 판독 가능 |

### 15.2 우선순위

적 공격 예고 → 내 캐릭터와 체력 → 내 수동 기술 → 아군 구조 표시 → 아군 공격 효과 → 배경 장식 순서로 중요도를 둔다.

아군 마법 효과는 내 효과보다 투명하게 표현한다. 성능 설정에서 파편 수, 불꽃 입자 수, 잔상 지속시간, 빛의 수를 줄일 수 있다. 효과 강도를 낮춰도 공격 방향, 위험 표시, 빙결 여부는 남는다.

적 공격 표시는 빨간색만으로 구분하지 않고 원·선·부채꼴 모양과 채워지는 움직임을 함께 사용한다. 파티원 구분도 색뿐 아니라 작은 이름과 소환수 소유 표시를 제공한다.

### 15.3 카메라

자유 회전과 확대·축소는 유지한다. 시작 시 전장을 읽기 좋은 약간 높은 시점을 주되 강제로 고정하지 않는다. 최대 확대에서도 가까운 적의 예고가 화면 밖으로 지나치게 잘리는지 확인한다.

적 예고를 알아보는 데 필요한 시야를 효과나 골렘 모델이 지속적으로 가리면 투명도와 크기를 조절한다. 화면 흔들림은 선택 사항이며 기본은 약하게 한다.

### 15.4 소리

화염은 짧은 발사음과 불길, 번개는 타격음과 잔류 전기, 얼음은 시전음과 결정 파열음, 골렘은 준비 돌 소리와 낮은 충격음을 사용한다.

같은 소리가 적 수만큼 중복 재생되지 않게 재생 수와 최소 간격을 제한한다. 보스와 위험 예고음은 일반 적 타격음보다 구별되어야 한다. 배경음, 효과음, UI 소리 음량은 따로 조절하도록 계획한다.

## 16. UI와 첫 방문 안내

### 16.1 전투 화면

- 상단: 남은 시간과 현재 구간, 보스 등장 시 체력.
- 캐릭터 가까이 또는 하단: 내 체력, 경험치, 레벨.
- 우하단: 화염 파동과 대시, 재사용 대기시간 숫자와 채움.
- 좌측: 팀원 체력, 쓰러짐, 구조 방향.
- 작은 빌드 영역: 보유 마법·소환수와 단계.

골렘 자동 강타의 대기시간은 확인할 수 있게 두되 수동 버튼처럼 보이지 않게 한다. 버튼처럼 표시하면 플레이어가 직접 눌러야 하는 기술로 오해한다.

### 16.2 첫 30초

1. “이동하면 마법과 골렘이 자동으로 싸웁니다.”
2. 적이 접근하면 “E: 대시 / Q: 전방 화염 파동”을 짧게 표시한다.
3. 첫 경험치 수집 때 성장 막대가 채워지는 것을 강조한다.
4. 첫 선택에서 “새 능력을 배우거나 지금 능력을 강화하세요”를 보여준다.

긴 설명 팝업을 연속으로 열지 않는다. 기본 조작을 안 뒤에는 안내를 반복하지 않고 설정에서 다시 볼 수 있게 한다.

### 16.3 메뉴와 실패 설명

패배 화면에 마지막으로 피해를 준 적 유형이나 놓친 위험을 표시할 수 있으면 제공한다. 시스템이 정확히 추적하지 못한 원인을 추측해 표시하지 않는다.

파티원이 아직 싸우고 있으면 개인 결과 대신 구조 대기 또는 관전 상태를 보여준다. 팀이 끝나기 전에 “다시 도전” 버튼이 전장을 재설정하지 않게 한다.

## 17. 장기 성장과 반복 플레이

### 17.1 한 판 성장과 계정 성장 분리

마법 단계, 이번 판의 레벨, 임시 강화는 매 판 초기화된다. 설정, 클리어 기록, 해금한 시작 소환수와 외형은 계정에 남긴다.

첫 저장 버전에서는 공격력 영구 증가나 끝없는 능력치 강화보다 선택지 해금을 우선한다. 새 친구가 기존 플레이어와 같은 파티에서 의미 있게 싸울 수 있어야 한다.

### 17.2 해금 과제 예시

| 과제 | 보상 제안 | 단계 |
| --- | --- | --- |
| 첫 판 완료 | 기록 페이지 활성화, 기념 칭호 | B |
| 골렘 강타로 적 여러 마리 제압 | 골렘 외형 문양 | B |
| 첫 보스 처치 | 드래곤 시작 선택지 해금 | B |
| 친구 구조 성공 | 협동 배지 또는 감정 표현 | B |
| 서로 다른 마법 조합으로 승리 | 빌드 기록과 외형 조각 | C |

모든 과제를 솔로로 달성할 필요는 없지만, 필수 전투 능력 해금이 친구 초대를 강제하지 않도록 한다. 협동 배지는 외형 중심으로 둔다.

### 17.3 재화와 수익화

단계 A에서는 재화를 만들지 않는다. 단계 B에서도 재화가 해금 과제를 실제로 개선하는지 확인한 뒤 하나만 도입한다.

유료 요소를 넣는다면 외형, 소환수 스킨, 감정 표현부터 검토한다. 강한 소환수 판매, 레벨업 선택권 판매, 패배 직후 결제 부활 유도는 초기 설계에 포함하지 않는다. 가격·상품·판매 일정은 이 문서에서 확정하지 않는다.

## 18. 구현 구조와 성능 예산

### 18.1 상태를 먼저 정리

라운드는 `준비 → 카운트다운 → 전투 → 공동 선택 → 전투 → 결과`로 구분한다. 참가자는 `대기 / 전투 / 쓰러짐 / 구조 중 / 결과 / 연결 종료` 상태를 가진다.

동시에 여러 상태가 켜지는 변수 조합보다 하나의 명확한 상태와 전환 규칙을 둔다. 라운드 종료는 한 번만 처리하며 경험치·보상·정리도 중복 실행하지 않는다.

### 18.2 서버와 클라이언트

서버는 피해, 적 이동, 성장 선택, 재사용 대기시간, 경험치 지급, 구조와 승패를 결정한다. 클라이언트는 입력 요청, UI, 카메라, 입자와 소리를 담당한다.

클라이언트가 보낸 타깃·위치·강화 ID는 그대로 신뢰하지 않는다. 유효한 선택지인지, 기술을 쓸 수 있는지, 거리와 범위가 맞는지 서버가 확인한다. 효과를 안 보이게 만들었다고 공격 범위나 피해가 달라지면 안 된다.

### 18.3 처음의 성능 목표

다음은 측정 전의 예산이다. 특정 기기에서 달성했다고 주장하는 수치가 아니다.

- 4인 기준 보통 적 동시 수를 우선 현재 수준인 65 안에서 검증한다.
- 평상시에는 30FPS 이상을 목표로 하고, PC에서는 60FPS를 목표로 한다.
- 적·소환수 AI 판단 주기와 위치 표현 주기를 분리한다.
- 밀집도 탐색은 일정 간격으로 수행하고 매 프레임 모든 적 쌍을 비교하지 않는다.
- 전투 효과는 기기와 중요도에 따라 입자·광원·파편 수를 조절한다.
- 경험치 구슬은 개수 제한에 도달하면 합쳐 총량을 보존한다.
- 모든 투사체·이벤트 연결·효과는 사망·이탈·라운드 재시작 때 정리한다.

단순히 적 수를 줄여 쉬워졌다면 공격 구성과 정예 비중으로 압박을 재조정한다. 성능 옵션 때문에 중요한 공격 예고가 사라지지 않아야 한다.

### 18.4 코드 정리 방향

기능이 늘기 전에 라운드 처리, 능력 데이터, 피해·상태 이상, 소환수 AI, 적 출현, UI·효과를 분리한다. 새 기능마다 기존 긴 스크립트에 조건을 계속 덧붙이는 방식은 피한다.

밸런스 수치는 한곳에서 관리하고 UI 설명이 같은 값을 참조하도록 한다. 설치기는 소스에서 다시 생성하며 직접 고치지 않는다. 기획 변경으로 게임 동작을 바꾸면 실제 코드와 설치기까지 함께 갱신한다.

### 21.3 기록할 지표

첫 경험치 수집 시점, 첫 선택 시점, 판당 선택 횟수, 생존 시간, Q·E 사용 횟수, 쓰러짐과 구조 횟수, 적 종류별 피해, 선택률, 강타 헛공격 비율, 프레임 시간과 남은 효과 객체 수를 기록한다.

단계 A의 초기 가설은 “첫 선택 20~30초”, “한 판에서 대부분 Q·E를 한 번 이상 사용”, “원인을 설명할 수 있는 패배”, “테스트 참가자가 자발적으로 한 번 더 플레이”다. 아직 달성한 결과가 아니다.

## 23. 다음 구현 묶음 제안

바로 다음 작업은 **라운드·협동 선택 상태를 정리하고, 골렘의 보이는 범위를 실제 피해와 맞추며, 경험치 손실을 없애는 것**이다. 그다음 속도형·원거리형 적을 한 종류씩 추가한다.

이 순서라면 새로운 콘텐츠를 더할 때마다 기존 협동·성장 규칙을 다시 뜯어고칠 가능성이 줄어든다. 드래곤과 보스는 기본 버전을 실제 친구들과 플레이한 피드백을 받은 뒤 진행한다.
