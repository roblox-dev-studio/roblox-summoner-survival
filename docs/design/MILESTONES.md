# 개발 마일스톤과 인수 기준

2026-10-16 · 팀 검토 초안. [한 장 요약](FIRST_VERSION.md) · [상세 기획](GAME_DESIGN.md).

**소환수는 이번 출시 준비 범위에서 제외한다.** 현재 골렘 구현은 후속 재사용을 위해 보존하고, M0에서 기본 플레이와 분리한다. 이 문서의 M0~M6는 아직 계획이다. 이미 통과한 솔로 전투·레벨업·재시작·하체 모션 증거는 [PLAYTEST_NOTES](../PLAYTEST_NOTES.md)에 있으며 새 기능의 통과 증거가 아니다.

## 일정 가정과 우선순위

기간은 세 명이 각각 하루 약 4시간을 실제 작업에 쓰고, 기능별 작업과 리뷰를 병행한다는 가정이다. AI 구독 수나 코드 생성 속도를 완성 속도로 환산하지 않는다. 아래 합계는 약 16~27 작업일이며 외부 테스터 모집·플랫폼 심사·큰 재작업은 제외한다. 확정 출시일이 아니며 **M1 종료 후 실제 처리량으로 다시 산정**한다.

| 순서 | 버전/결과 | 예상 작업일 | 선행 조건 |
| --- | --- | --- | --- |
| M0 | 소환수 없는 기준 빌드 | 0.5~1일 | 현재 검증 소스 확보 |
| M1 | 마법·증강으로 세 빌드 구별 | 2~4일 | M0 |
| M2 | 첫 3분과 초보자 시험 | 2~3일 | M1 |
| M3 | 3클래스·해금·저장 기반 | 3~5일 | M2 재미/이해 기준 통과 |
| M4 | 수집·무료 가챠·제작 | 3~5일 | M3 저장 검증 |
| M5 | 모바일·성능·품질·보안 | 3~5일 | M4 기능 연결 |
| M6 | 제한 외부 시험·출시 판단 | 2~4일 | M5, 테스터 확보 |

v0.1은 M0~M2, v0.2는 M3~M4, v0.3 출시 후보는 M5~M6다. v1.0 명칭은 실제 출시 범위 승인 시 붙인다. 마일스톤 통과 전에 다음 단계의 대량 콘텐츠를 만들지 않는다. 필요한 인터페이스 합의·작은 탐색은 가능하지만 준비한 파일을 적용 완료로 세지 않는다.

## M0 — 현재 구현을 새 방향에 맞추기

- 기본 골렘 생성·자동 공격·골렘 강화 카드·골렘 HUD를 기본 모드에서 제외한다.
- 골렘 코드/외부 소재/출처/과거 검증은 보존한다. 미리보기 설정이 새 게임으로 새어 나오지 않게 한다.
- 화염 시작, Q/E, 경험치, 3선택, 승패/재시작 흐름을 유지한다.
- README의 구현 상태와 새 설치기의 실제 동작을 함께 갱신한다.

**인수:** 새 Baseplate에 설치한 실제 플레이에서 골렘과 관련 카드가 나오지 않는다. 자동 공격, 첫 레벨업, 선택 후 복귀, 180초 승리, 사망, 재시작 2회가 정상이다. 재시작 후 이전 주문·XP·쿨다운·이펙트가 남지 않는다. 시간 조절 등 시험용 조작은 기록하고 실제 3분 플레이와 구별한다.

## M1 — 마법을 고르는 재미

- 화염술사 시작 주문/패시브를 만들고, 상세 기획의 카드 12개를 데이터와 효과에 연결한다.
- 첫 선택 고정, 조건/상한/중복 제외, 조합 후보 보장, 후보 부족 시 회복 보충을 구현한다.
- 불 집중 / 열충격 / 빙결 전도의 세 빌드를 실제로 만들 수 있게 한다.
- 피해와 발동 규칙은 서버에서 처리한다. 추가 폭발·연쇄가 서로 무한 재발동하지 않게 한다.
- 선택 설명과 적용 수치가 일치하게 한다. 주문별 발사/명중/처치 표현을 구별한다.

**인수:** 조건 미충족·최대 단계·이미 선택한 조합의 후보 제외를 로직으로 검증한다. 같은 적 배치에서 세 빌드의 화면과 피해·제어 차이를 확인한다. 자연 진행으로 3분 내 조합 완성 여부와 사용 시간을 기록한다. 시험용 강제 강화만으로 빌드 재미를 통과시키지 않는다.

**보류 조건:** 모든 선택이 피해량 증가처럼 보이거나 한 빌드가 다른 선택을 압도하면 M2 전에 수정한다. 새 주문 수를 늘리는 것으로 덮지 않는다.

## M2 — 첫 3분과 재도전

- 추적형과 방향 예고가 있는 돌진형을 배치하고 30/90/150초 구간의 리듬을 조정한다.
- 첫 공격 10초 이내, 첫 증강 20~30초, 한 판 선택 5~7회를 목표로 조정한다.
- 상황별 한 줄 안내, 건너뛰기, 결과/한 번 누르는 재도전을 연결한다.
- 첫 처치/XP/선택/대시/종료/재도전 이벤트의 의미와 분모를 정한다. 저장 전 단계에서는 시험 로그로 측정해도 된다.
- 개발자가 아닌 5명이 설명 없이 플레이하도록 모집한다. 참여 시간은 위 작업일 추정 밖이다.

**인수:** 4/5가 도움 없이 첫 증강 선택, 3/5가 선택 차이 설명, 4/5가 승패 결과 도달, 3/5가 보상이나 요청 없이 재도전한다. 작은 표본은 문제 발견용이다. 원인·사용 버전·기기·관찰을 남기고 실패 구간을 수정한다.

**v0.1 완료:** 마법/증강만으로 첫 판과 재도전 이유를 보여준다. 이때 클래스/가챠 미구현은 버그가 아니라 다음 단계다.

## M3 — 클래스와 계정 진행

- 화염술사·빙결술사·뇌전술사 3종의 시작 마법/패시브/Q를 연결한다. HP·속도·기본 XP 규칙은 동일하게 둔다.
- 첫 클리어/누적 3클리어 해금, 클래스 선택, 미해금 미리보기, 주문별 첫 선택을 구현한다.
- 계정 프로필 스키마·버전 이행·동시 접속 충돌 처리·저장 실패/재시도를 먼저 정의한다.
- 클래스 해금/선택과 튜토리얼 진척을 저장한다. 매 판 전투 강화는 초기화한다.

**인수:** 세 클래스 모두 새 판/사망/재시작/재접속에서 기본값과 선택이 맞는다. 해금 요청 재전송으로 중복 보상이 생기지 않는다. 저장 실패를 성공으로 표시하지 않는다. 여러 서버의 동일 계정 갱신과 데이터 버전 이행을 검증한다. 실제 플레이에서 시작 방식과 Q의 차이를 확인한다.

## M4 — 수집·희귀도·무료 가챠

- 외형 12개(일반6/희귀4/영웅2), 장착/미리보기/도감/출처 기록을 준비한다.
- 별도의 고정 첫 플레이 외형, 클리어 티켓, 패배 조각, 중복 조각, 확정 제작을 연결한다.
- 70/25/5 기본 확률, 10회 희귀 이상·30회 영웅 천장과 현재 확률 표시를 구현한다.
- 재화 차감·추첨 결과·중복 변환·천장·처리 식별자를 동일 프로필 갱신으로 다룬다.
- 무료 티켓에 Robux 구매나 유료 획득 배율을 연결하지 않는다. 클래스는 플레이 해금이다.

**인수:** 첫 보상 1회, 티켓 부족, 중복 클릭, 중복 당첨, 카운터 9/29 경계, 두 천장 동시 조건, 확정 제작, 재접속/서버 종료/저장 실패를 검증한다. 확률 데이터 총합과 표시가 일치한다. 통계 샘플은 확률 구현 점검의 보조이며 보상 저장 성공의 증거로 쓰지 않는다.

**경제 검수:** 10/30/100판의 예상 티켓·조각·중복과 실제 시험 획득을 비교한다. 원하는 외형에 도달하는 시간이 납득 가능한지 확인한다. 단순히 오래 걸리게 만들거나 유료 구매로 불편을 해결하지 않는다.

## M5 — 지원 기기와 품질

- 시작 시 실제 보유 PC/모바일 기준 기기, 해상도, 그래픽 설정을 명시한다. 기준 기기 없이 “최적화 완료”를 선언하지 않는다.
- 모바일 이동·대시·Q·카드 선택·결과를 실제 터치로 검증한다.
- 최대 적/투사체/효과 상황에서 프레임 시간·메모리·네트워크 부하를 기록한다. 임시 목표는 모바일 지속 30fps 이상이며 기기 선정 후 확정한다.
- 효과 품질 단계, 흔들림/섬광 감소, 음량, 작은 화면 HUD, 위험 예고 가독성을 검수한다.
- 네트워크 입력·빈도·상태 검증, 과도한 요청, 재시작 누적, 서버 권한, 외부 에셋 출처를 점검한다.

**인수:** 지원 기기에서 3판 연속 플레이/재시작, 이동/선택/사망/재접속을 통과한다. 자동 검사와 엔진 시험에 더해 화면을 보고 소리를 듣는다. 동일 상황의 전후 자료로 성능 저하나 메모리/객체 누적을 확인한다. 치명 오류나 저장 손실이 남으면 공개 단계로 넘기지 않는다.

## M6 — 작은 외부 시험과 공개 판단

- 초보자 시험을 수정 빌드로 반복하고, 추가 외부 참가자의 클래스/조합/재도전 패턴을 관찰한다.
- 첫 선택 도달, 첫 판 이탈, 재도전, 클래스별 사망, 수집 속도를 버전·기기별로 비교한다.
- 확보된 표본으로 판단 가능한 항목과 부족한 항목을 분리한다. D1/D7은 관찰 기간과 코호트가 있어야 계산한다.
- 설치/실행 경로, 최신 place와 커밋, 알려진 문제, 복구 경로를 팀에 인계한다.

**출시 판단:** 치명 결함 해소, 실제 반복 플레이 근거, 지원 기기 검증, 출처/정책 확인 후 사용자가 공개 범위를 승인한다. 이 계획 작성이나 테스트 통과가 자동 게시 승인은 아니다. 유료 상품은 별도 결정이며 가챠 수익 없이도 전투가 성립해야 한다.

## 세 명의 분담과 병합

| 기능 영역 | 우선 납품 | 다른 영역과 맞출 계약 |
| --- | --- | --- |
| 전투·마법 | 주문/증강 효과, 클래스 전투 규칙, 공격 연출 | 주문 ID, 피격/상태 이상, 연출 이벤트 |
| 적·월드 | 출현/돌진/난도, 이동 공간, 성능·카메라 | 적 상태, 전투 시간, 생성/제거 책임 |
| 성장·사용자 흐름 | 선택지/튜토리얼/HUD/결과, 저장·수집 | 카드 데이터, 계정/라운드 상태, 보상 식별자 |

각 영역의 서버·클라이언트를 같은 담당이 연결한다. 담당은 이슈마다 바꿀 수 있다. 전투 담당이 효과까지 혼자 모든 자산을 만들라는 뜻은 아니다. 외부 소재 사용 시 출처와 적용 경로를 함께 납품한다.

- 이슈는 목표·소유 파일·완료 조건 1~3개·검증 자료로 작게 만든다.
- 공유 파일은 한 명이 수정하고 나머지는 계약/별도 모듈을 준비한다. 설치기는 병합 후 재생성한다.
- 통합자는 세 명이 순번으로 맡는다. 실제 Studio 조작은 해당 세션 소유자 한 명이 한다.
- 완료 보고는 변경·검증·남은 문제·다음 인계만 적는다. 새 증거 없는 상태 문서를 늘리지 않는다.
- 기능 변경은 관련 기획/계약 문서, 실제 관찰은 PLAYTEST_NOTES, 소재는 ASSET_CREDITS를 함께 갱신한다.

### 처음 만들 작업 세 개

1. **M0 기본 골렘 분리:** 전투/세션/선택지/HUD의 현재 사용처를 정리하고 회귀. 연결부 담당 1명 지정.
2. **M1 카드 데이터 계약:** 카드 ID·선행 조건·상한·설명·서버 적용 경계를 합의. M0 수정과 같은 파일을 동시에 편집하지 않음.
3. **M1~M2 돌진형 예고 시제품:** 적 모듈 안에서 시험하고 기존 적 레코드 계약 유지. 합치는 시점은 M1 전투 연결 뒤.

## 일정이 밀릴 때 줄이는 순서

새 맵/5분 모드/원거리 정예, 추가 외형 변형, 장식 연출부터 후속으로 보낸다. 외형 수량을 바꾸면 풀·아이템별 확률·제작 비용·도감도 함께 갱신한다. 클래스 수나 출시 범위 변경은 팀과 합의하고 한 장 요약도 고친다.

자동 공격/증강 선택/재시작, 보상 중복 방지, 저장 복구, 공격 예고 가독성을 줄여 일정을 맞추지 않는다. **소환수·협동·유료 가챠는 일정 지연의 보상 콘텐츠로 끼워 넣지 않는다.** 소환수 재개 조건은 상세 기획 14절을 따른다.
