# 마법 서바이벌 상세 기획

2026-10-16 / 팀 검토 초안 / 기준 구현 `ab247ef`.

사용자가 정한 방향은 **뱀파이어 서바이벌형 3D 게임 + 마법 + 증강 + 다양한 클래스**, 이후 수집·희귀도·가챠다. **소환수는 나중에 도입한다.** 이하 클래스 이름, 숫자, 보상량, 확률, 일정은 초기 시험안이다. 팀 플레이 결과에 따라 바꾸며 확정 제작 약속으로 취급하지 않는다.

빠른 공유는 [첫 버전 한 장 기획](FIRST_VERSION.md), 실행 순서는 [마일스톤](MILESTONES.md)을 사용한다. 이 문서는 의도와 규칙, `PLAYTEST_NOTES.md`는 실제 증거를 관리한다.

## 1. 목적과 성공 가설

사업 목적은 지속 가능한 수익이다. 먼저 “한 판이 재미있어서 또 하는가”, 다음으로 “다른 클래스와 수집을 위해 돌아오는가”, 마지막으로 “외형에 비용을 지불할 이유가 있는가”를 검증한다. 매출이나 흥행을 보장하는 설계는 아니다.

- **즉시 만족:** 짧은 이동만으로 공격이 시작되고 적이 맞고 쓰러지는 결과가 분명하다.
- **선택의 만족:** 같은 불·얼음·번개라도 증강 선택에 따라 공격 모양과 적을 상대하는 방법이 달라진다.
- **반복의 이유:** 다른 빌드, 클래스별 목표, 얻고 싶은 외형을 제시한다.
- **작은 팀의 생산성:** 전장·공격·효과를 재사용하고 새 규칙은 작은 모듈과 데이터로 추가한다.

색만 다른 주문, 피해량만 올라가는 카드, 전투 대신 긴 로비/상점 구경으로 시간을 채우는 구성은 이 가설을 입증하지 못한다.

## 3. 플레이 구조와 버전 경계

### 한 판 안의 루프

이동으로 적과 거리를 조절 → 자동 마법으로 처치 → 경험치 수집 → 3개 증강 중 1개 선택 → 공격 방식 변화 → 위험 구간 돌파 → 결과/재도전.

플레이어는 WASD/가상 스틱으로 이동하고 E/화면 버튼으로 대시한다. Q는 클래스의 위기 대응 기술이다. Space 점프는 보조 이동이며 점프를 연속 입력해야만 피할 수 있는 공격을 첫 버전에 넣지 않는다. 카메라는 3인칭으로 주변 적을 볼 수 있어야 한다.

### 한 판 밖의 루프

클래스/외형 선택 → 한 판 → 클래스 해금 진척·무료 보상 → 원하는 외형 확인 → 다른 빌드나 목표로 재도전. 결과 화면에는 다음 목표 **하나**를 우선 노출한다.

| 유지 여부 | 데이터 |
| --- | --- |
| 매 판 초기화 | 전투 레벨, 경험치, 습득 주문, 증강, HP, 쿨다운, 적·투사체 |
| 계정 유지(M3 이후) | 해금 클래스, 장착 외형, 도감, 무료 티켓/조각, 천장 횟수, 튜토리얼/보상 수령 기록 |
| 첫 출시 제외 | 영구 공격력 구매, 장비 강화 실패, 거래, 경매장, 소환수 성장, 대규모 스토리 |

v0.1은 솔로 3분/클래스 1개로 전투 재미를 증명한다. v0.2는 클래스 3개와 수집을 붙이는 비공개 시험 버전이다. v0.3은 모바일·저장·초보자 테스트를 마친 공개 후보이며 게시 승인은 별도다. 소환수는 v0.4 이후 후보로만 둔다.

## 4. 마법과 세 가지 빌드

초기 자동 주문은 **불·얼음·번개 3종**이다. 전투 중 최대 3종을 보유하고 기본 단계는 각각 5가 상한이다. 주문은 자동 조준/자동 발사하며 희귀 외형을 장착해도 피해·범위·판정은 바뀌지 않는다.

| 주문 | 전투 역할 | 읽혀야 할 표현 | 약점/검수 |
| --- | --- | --- | --- |
| 화염탄 | 밀집한 적에게 폭발 피해 | 날아가는 불꽃, 적중 지점, 폭발 경계 | 한 적에게 겹친 판정으로 중복 피해가 나지 않음 |
| 얼음창 | 위험한 적 제어, 이동 경로 확보 | 창의 진행 방향, 얼어붙은 적, 해제 시점 | 제어 시간이 무한히 갱신되어 모든 적을 멈추게 만들지 않음 |
| 연쇄 번개 | 여러 적 사이의 분산 피해 | 처음 맞은 적과 다음 연결 경로 | 적이 없을 때 허공 연결/무한 연쇄 없음 |

첫 판은 화염탄으로 시작한다. 시작 주문 외의 두 주문은 증강으로 배운다. 세 주문을 모두 배우는 것이 항상 최선이 되지 않도록 강화 횟수와 기회를 제한한다.

| 빌드 | 핵심 선택 | 플레이 변화 | 미구현 요소 |
| --- | --- | --- | --- |
| 화염 집중 | 화염 단계 + 분열 화염 | 적을 모으고 폭발이 겹칠 위치를 만든다 | 추가 탄환 분기 |
| 열충격 | 화염 강화 + 얼음 습득 + 열충격 | 돌진 적을 얼리고 폭발을 연결한다 | 빙결 상태를 읽는 보너스 타격 |
| 빙결 전도 | 번개 강화 + 얼음 습득 + 빙결 전도 | 앞줄을 늦추고 뒤쪽 적까지 연쇄한다 | 조건부 추가 연쇄 |

조합 명칭만 바꾸지 않는다. 동일 난도에서 선택 전후 공격 형태와 유리한 적 배치가 달라져야 한다. 정답 빌드가 하나로 고정되면 신규 주문 대신 해당 상호작용부터 수정한다.

## 5. 증강 시스템

### 제시 규칙

- 레벨업마다 3개 중 1개. 솔로에서는 선택 중 전투 시간을 멈춘다.
- 목표는 3분에 **5~7회 선택**, 첫 선택은 전투 시작 후 **20~30초**다. 현재 경험치 곡선의 실제 결과를 측정해 조정한다.
- 화염술사의 첫 선택은 얼음 습득/번개 습득/화염 강화로 고정한다. 튜토리얼 선택도 실제 강화로 유지한다.
- 이후 일반 선택은 가능하면 습득·형태 변화·생존 중 서로 다른 목적을 제시한다. 같은 카드 중복, 최대 단계, 선행 조건 미충족 카드는 제외한다.
- 한 판 조합 증강은 하나만 허용한다. 열충격을 골랐다면 빙결 전도는 그 판 후보에서 빠진다.
- 선행 조건을 충족하면 다음 선택에서 조합 카드 1개를 보장한다. 두 조합이 모두 가능하면 하나를 무작위 제시하되 이번 판 보유 조합을 강제로 교체하지 않는다.
- 남은 유효 후보가 부족하면 회복/자석/이동 보충 카드를 사용한다. 소유하지 않은 주문 전용 강화는 제시하지 않는다.
- v0.1에는 리롤·밴·유료 재선택을 넣지 않는다. 카드 운이 나빠 아무 빌드도 만들지 못하는 경우는 후보 편성으로 먼저 해결한다.

### 클래스 확장 시 카드 풀

빙결술사 시작 시 I1 대신 화염 습득 카드(F0)를, 뇌전술사는 L1 대신 F0를 사용한다. 기본 주문 습득 카드는 세 원소별로 정의하되 이미 보유한 주문은 후보에서 제외한다. v0.1의 12개는 화염술사 기준이며 다클래스 데이터 확장은 M3의 작업이다.

## 6. 클래스 — 다양한 시작과 플레이 방식

클래스는 마법 도구를 고르는 방식의 차이다. **기본 HP100·이동 속도22·경험치 규칙은 동일**하고 모든 클래스가 모든 기본 주문을 배울 수 있다. 클래스에 희귀도를 붙이거나 가챠로만 해금하지 않는다.

| 클래스(가칭) | 시작 주문 | 패시브 초안 | Q 초안 | 해금/버전 |
| --- | --- | --- | --- | --- |
| 화염술사 | 화염탄 | 화염 폭발 반경 +15% | 기존 전방 화염 파동 | 기본 지급, v0.1; 패시브는 신규 |
| 빙결술사 | 얼음창 | 빙결 지속 +0.2초 | 주변 적을 짧게 얼리는 서리 파동 | 첫 3분 클리어, M3 |
| 뇌전술사 | 연쇄 번개 | 기본 연쇄 대상 +1 | 가까운 적 무리에 즉시 낙뢰 | 누적 3판 클리어, M3 |

Q는 일단 재사용 7초, E 대시는 공통 3초로 시작하고 실제 생존력 차이를 보고 조정한다. 패시브와 Q가 함께 지나치게 유리하면 피해를 숨겨 보정하지 말고 설명 가능한 규칙을 바꾼다. 체험 화면에서 미해금 클래스의 시작 공격/Q를 볼 수 있게 한다.

v0.1의 선택 화면은 클래스 1개를 고르기 위해 별도 로비를 강제하지 않는다. v0.2부터 세 클래스를 제시한다. 시간술사·비전술사·저주술사 등은 후보 이름만 보관하며 세 클래스가 구별되기 전 추가 제작하지 않는다.

## 7. 적·전장·한 판의 리듬

맵은 기존 전장 1개를 다듬는다. 통로/장애물로 회피가 막히지 않게 하고 경험치와 공격 예고가 바닥에서 구별되어야 한다. 보스 모델이나 새 지형 제작으로 첫 재미 검증을 늦추지 않는다.

| 경과 시간(전투 시간 기준) | 구성 목표 | 플레이어가 경험할 변화 |
| --- | --- | --- |
| 0~30초 | 낮은 밀도의 추적형, 가까운 첫 적과 XP | 입력 학습과 첫 증강 |
| 30~90초 | 추적형 무리 + 한 번에 적은 수의 돌진형 | 대시 사용, 조합 준비 |
| 90~150초 | 서로 다른 방향의 적, 밀집 구간 | 조합이 작동하고 길을 만드는 느낌 |
| 150~180초 | 예고된 마지막 공세, 지나친 체력 증가 억제 | 성장한 화력을 쓰며 생존 마무리 |

돌진형은 발동 전 방향을 보여주고, 돌진 중 급격히 방향을 틀지 않는다. 원거리형과 정예는 M3 이후 후보이며 각 1패턴부터 시작한다. 순간이동해 포위하거나 화면 밖에서 예고 없이 치명 피해를 주지 않는다.

5분 모드는 3분 플레이가 재미있지만 조합을 완성해 쓰는 시간이 부족하다는 관찰이 있을 때만 만든다. 단순히 보상 획득을 늦추기 위해 시간을 늘리지 않는다. 긴 모드 도입 시 첫 3분 튜토리얼과 구별하고 보상량도 별도 비교한다.

## 8. 첫 3분 튜토리얼과 초반 몰입

아래 시간은 로딩 완료 후 조작 가능한 시점 기준 목표다. 서버 대기·다운로드 시간은 별도로 측정한다. 긴 설명창, 강제 카메라 연출, 입장 직후 상점/가챠 팝업을 넣지 않는다.

| 시점 | 실제 경험 | 안내/검증 |
| --- | --- | --- |
| 0~5초 | 캐릭터와 가까운 적, 시작 주문이 보임 | “이동하며 살아남으세요” 한 줄, 진행 시간 표시 |
| 5~10초 | 자동 공격과 첫 처치 | 피해 반응·처치 소리·XP 경로가 구별됨 |
| 10~20초 | XP를 향해 이동 | 가까운 구슬에 한 번만 안내; 습득하면 사라짐 |
| 20~30초 | 첫 선택 | 3개의 실제 효과 미리보기/짧은 설명; 선택 후 즉시 사용 |
| 30~60초 | 느린 돌진 예고, 대시로 빠져나갈 기회 | E/터치 버튼 한 번 강조. 실패해도 즉사시키지 않음 |
| 60~120초 | 추가 증강과 조합 조건 충족 | “얼음 + 화염 강화 → 열충격” 등 현재 가능한 목표만 표시 |
| 120~180초 | 달라진 공격으로 마지막 무리 대응 | 도전 완료까지 남은 시간과 성장 차이 강조 |
| 결과 | 선택한 빌드·보상·다음 목표 | 다시 도전 우선 버튼, 다른 선택/클래스는 보조 버튼 |

튜토리얼은 조작/첫 처치/XP/첫 선택/대시 사용/한 판 종료를 독립 기록한다. 이미 한 행동을 반복 요구하지 않는다. 중간 이탈자는 미완료 단계만 간단히 다시 안내한다. 숙련자는 건너뛰고 설정에서 다시 볼 수 있다. 건너뛰기로 보상 중복이나 전투 이득이 생기지 않는다.

첫 선택 완료 보상으로 **정해진 일반 외형 1개**를 예고하고 결과에서 받게 한다(M4 이후). 무작위 당첨처럼 연출하지 않는다. 첫 플레이 보상은 실패해도 유지하되 한 계정에 한 번만 지급한다. 클래스 해금까지의 진척은 숫자로 보여주고 보상 수령 때문에 재도전이 여러 화면 뒤로 밀리지 않게 한다.

첫 10초의 이펙트는 실제 1단계 공격이다. 최종 강화 효과를 미리 보여주고 실제 성장 차이가 없어지는 기존 골렘 미리보기 방식을 새 주문에 복제하지 않는다.

Roblox도 첫 경험의 이탈 구간과 온보딩 목표를 측정하며 개선하도록 설명한다. 위 시간과 통과 기준은 이 팀의 시험 가설이며 플랫폼 성공 기준이 아니다. [Roblox Onboarding](https://create.roblox.com/docs/production/game-design/onboarding)

## 9. 수집과 희귀도

수집은 전투로 얻는 장기 목표다. “새 빌드를 시도할 수 있는 해금”과 “갖고 싶은 외형”을 분리한다.

| 수집 종류 | 획득 경로 | 전투 영향 |
| --- | --- | --- |
| 클래스 | 공개된 플레이 업적 | 다른 시작·패시브·Q; 동일한 기본 스탯 |
| 주문/증강 도감 | 실제 습득·발동·클리어 기록 | 정보/목표 표시, 영구 피해 보너스 없음 |
| 완드/마법서 외형 | 무료 가챠 또는 조각 확정 제작 | 외형만 변경, 판정 동일 |
| 주문 스타일 | 무료 가챠 또는 확정 제작 | 색/무늬/잔광 변화, 적 예고 가독성 유지 |
| 칭호 | 클래스/빌드별 업적 | 표현만 변경 |

초기 랜덤 수집 풀은 **12개 외형(일반6·희귀4·영웅2)**를 상한으로 제안한다. 예: 완드6, 마법서 표지3, 주문 스타일3. 외형 장착 UI를 먼저 만들고 수집 연출을 붙인다. 도감에는 실루엣·미리보기·획득 경로·확정 제작 비용을 보여준다.

희귀도는 이름·아이콘·테두리·제작 디테일로 표현한다. 색각 차이 때문에 색만으로 구별하지 않는다. 영웅 외형도 폭발 범위가 커 보이거나 적 공격 예고를 가릴 정도로 밝아지면 안 된다. 첫 버전에서 전설/신화/초월 등의 등급을 계속 추가하지 않는다.

**매 판 증강은 전투 빌드 선택, 외형 희귀도는 계정 수집 분류다.** 둘을 같은 강화 재료나 같은 뽑기로 섞지 않는다. 처음에는 증강에 희귀도 추첨을 넣지 않고 선행 조건과 효과 종류를 표시한다.

## 10. 무료 가챠·중복·확정 획득

M4에서는 **플레이로만 얻는 무료 티켓**을 사용한다. Robux, Robux로 살 수 있는 재화, 유료 행운/보상 배율과 연결하지 않는다. 티켓 판매는 이 설계의 범위가 아니다.

### 보상 초안

- 3분 클리어: 무료 티켓 1장 + 조각 10개. 첫 결과 화면에서 획득 이유를 보여준다.
- 패배: 전투 생존 30초마다 조각 1개, 최대 5개. 선택 화면 시간은 제외한다. 시작 후 바로 나가기는 보상 없음.
- 첫 증강 완료: 고정 일반 외형 1개, 계정당 1회. 랜덤 풀 12개와는 별도 튜토리얼 보상이다.
- 티켓 1장 = 외형 1개. 중복은 일반5/희귀15/영웅50 조각으로 자동 전환한다.
- 확정 제작 초안: 일반30/희귀90/영웅300 조각. 중복은 진행에 도움이 되지만 신규 획득처럼 표시하지 않는다.
- 매일 접속하지 않았다고 누적 보상이나 천장을 잃게 하지 않는다. 시간 제한 배너는 초기 범위에서 제외한다.

### 기본 확률과 천장 초안

일반70% / 희귀25% / 영웅5%. 같은 등급 안의 외형은 균등 확률이며 중복도 나온다. 초기 확률은 변경 전후 재화 흐름과 수집 속도를 비교해 확정한다.

| 상황 | 이번 뽑기 규칙 | 카운터 처리 |
| --- | --- | --- |
| 일반 상태 | 70/25/5 | 일반이면 두 카운터 +1; 희귀면 희귀 이상 카운터 0, 영웅 카운터 +1; 영웅이면 둘 다 0 |
| 희귀 이상 9회 연속 미획득 | 10번째는 희귀 또는 영웅만, 비율 25:5 | 희귀이면 희귀 이상 카운터 0, 영웅 카운터 +1; 영웅이면 둘 다 0 |
| 영웅 29회 연속 미획득 | 30번째는 영웅 확정; 위 조건보다 우선 | 둘 다 0 |

천장은 **등급 보장**이며 새 외형 보장이 아니다. 중복도 해당 등급 획득으로 카운터를 초기화한다. 고정 튜토리얼 보상과 확정 제작은 뽑기 카운터에 영향을 주지 않는다. 재접속해도 누적을 보존한다. “다음 영웅 확정까지 N회”와 현재 적용 확률을 버튼 옆에서 확인할 수 있게 한다.

연출은 1~2초를 목표로 하고 즉시 넘길 수 있다. 서버가 보상을 확정/저장한 후 연출한다. 근접 실패, 가짜 품절/시간 압박, 당첨처럼 보이는 중복 표시를 쓰지 않는다. 초기에 10연차·여러 배너·확률 증가 아이템은 만들지 않는다.

### 저장과 중복 지급 방지

보상/뽑기는 서버에서 처리한다. `roundId`/보상 식별자와 처리 기록, 티켓 차감, 결과, 도감/조각, 천장 상태를 한 프로필 갱신 안에서 다룬다. 동일 요청 재전송은 기존 결과를 돌려주고 다시 차감하거나 지급하지 않는다. 여러 서버에서 같은 프로필을 갱신하는 상황도 검증한다.

저장 실패 시 성공 연출이나 미확정 보상을 표시하지 않고 재시도 가능한 상태를 유지한다. 클라이언트가 보낸 희귀도·티켓 수·승리 주장·생존 시간을 신뢰하지 않는다. 직접 재화 편집, 중복 클릭, 연결 종료, 서버 종료 상황을 M4 인수에 포함한다.

## 11. 수익화 방향과 정책 경계

초기 수익화 후보는 **가격과 결과가 분명한 외형 직접 구매**다. 클래스 가챠, 필수 마법 판매, 유료 부활, 유료 증강 리롤, 영구 공격력 판매는 첫 출시 후보에서 제외한다. 가격은 외형 품질과 실제 관심을 확인한 다음 정하며 이 문서에는 매출 예측을 넣지 않는다.

유료 가챠는 필요성이 확인되면 별도 기획·검증한다. Roblox는 Robux 또는 Robux로 구매 가능한 재화로 받는 랜덤 아이템에 대해 가능한 결과와 실제 수치 확률 공개를 요구한다. 제한된 사용자에게는 `PolicyService`의 `ArePaidRandomItemsRestricted`에 따라 접근을 허용하면 안 된다. 확률이 바뀌는 유료 효과가 있으면 실제 변경 확률 표시도 필요하다. 무료 티켓을 판매하거나 유료 경로와 연결하면 정책 검토를 다시 해야 한다. [공식 Paid random items 정책](https://create.roblox.com/docs/production/monetization/paid-random-items)

이 문서는 출시 시점 정책/지역별 요건 확인을 대체하지 않는다. 실제 결제 상품 생성·구매·공개 게시를 수행하라는 지시도 아니다. 첫 유료 상품 도입 시 구매 처리/중복 지급/실패 복구와 사용자별 정책 처리를 별도 인수한다.

## 12. UI·모션·이펙트·사운드

- **HUD:** HP/경험치/남은 시간, 하단 Q/E 상태, 현재 마법/조합 아이콘. 전투 중 도감·상점 팝업은 숨긴다.
- **카드:** 무엇이 달라지는지 한 문장, 선행 조건, 현재→다음 단계, 실제 효과 미리보기. 수치만 긴 목록으로 나열하지 않는다.
- **결과:** 살아남은 시간·처치·빌드·보상·다음 목표. “다시 도전”은 한 번의 클릭/탭으로 접근한다.
- **모션:** 현재 CC0 R15 하체를 유지하며 출발/정지/점프/착지 연결을 검수한다. 사망 모션 때문에 전투 프로토타입 전체를 멈추지 않는다.
- **이펙트:** 불은 폭발, 얼음은 결정과 제어, 번개는 연결로 구별한다. 적의 위험 예고는 플레이어 효과보다 우선해서 읽혀야 한다.
- **사운드:** 시전/명중/처치/경고/선택/희귀 보상을 구분하고 동시 재생 수를 제한한다. 음악·음향 볼륨 조절과 실제 청취를 검증한다.
- **접근성/성능:** 화면 흔들기·섬광 감소 설정, 작은 화면의 버튼 겹침, 색 외 아이콘 표식, 낮은 효과 품질을 준비한다.

외부 소재는 출처·사용 조건·변환본·적용 경로를 기록하고 신뢰하지 않은 동봉 코드를 실행하지 않는다. 효과나 영상이 멋있어도 실제 전투 화면이 가려지면 채택하지 않는다.

## 13. 검증 지표와 판단

### 비개발자 5명 소규모 시험

진행자는 먼저 설명하지 않고 관찰한다. 동일 빌드/기기/버전과 중단 사유를 기록한다.

| 질문 | 임시 통과 기준 | 실패 시 우선 수정 |
| --- | --- | --- |
| 조작/성장을 이해하는가 | 5명 중 4명 도움 없이 첫 증강 선택 | 안내 위치·첫 XP 경로·카드 문구 |
| 선택 차이가 보이는가 | 5명 중 3명 자신의 선택이 바꾼 효과를 설명 | 주문 형태·조건 표시·타격 피드백 |
| 한 판이 이어지는가 | 5명 중 4명 결과 화면까지 도달(승리/패배 모두) | 오류·난도 급변·지루한 공백 |
| 다시 할 이유가 있는가 | 5명 중 3명 보상/요청 없이 자발적 재도전 | 빌드 다양성·조작·한 판 길이 |

5명 결과는 문제 발견용이며 시장성/통계적 유의성 근거가 아니다. 통과해도 흥행을 주장하지 않는다. 실패하면 보상량이나 광고로 덮지 않고 원인을 한 가지씩 수정해 다시 본다.

### 공개 전후 관찰

`session_ready`, `first_kill`, `first_xp`, `first_augment`, `first_dash`, `build_formed`, `run_end`, `retry`, `class_unlock`, `collection_claim`, `draw_resolved` 단계를 버전/입력기기와 함께 기록한다. 중복 이벤트와 중간 이탈 때문에 분모가 달라지지 않도록 정의한다. 원시 채팅이나 불필요한 개인정보는 수집하지 않는다.

- 첫 선택 도달률 = 첫 선택한 신규 플레이어 / 조작 가능한 신규 플레이어.
- 자발적 재도전율 = 결과 후 새 판을 시작한 사용자 / 결과를 본 사용자.
- 클래스별 클리어·사망 시점, 증강 선택률, 실제 조합 완성률을 비교한다.
- D1/D7은 첫 접속 날짜 코호트와 유입 경로를 구별한다. 소수 플레이를 전체 유지율로 일반화하지 않는다.
- 수집은 신규/중복 획득, 조각 유입/소비, 천장 도달, 도감 완성 시간을 확인한다.

Roblox는 유입을 크게 늘리기 전에 유지율·세션 참여 등을 살펴 개선하는 접근을 권장한다. 고정된 만능 D1 목표 대신 실제 Creator Dashboard의 비교 기준과 우리 표본을 함께 사용한다. [Analytics](https://create.roblox.com/docs/production/analytics), [Retention](https://create.roblox.com/docs/production/analytics/retention)

## 14. 후속 소환수와 확장 원칙

소환수는 v0.4 이후 후보다. M0에서 골렘을 기본 플레이에서 분리하되 재사용 가능한 코드·출처·검증 기록은 보존한다. 첫 후속 시험은 골렘 1종으로 하고 마법/증강과 상호작용할 때 실제 선택이 달라지는지 본다.

소환수 도입 조건: 마법 빌드와 클래스의 반복 플레이 근거, 저장 안정성, 지원 기기의 적/이펙트 성능 여유, 추가 조작/UI 없이 이해 가능한 역할. 조건 충족 전 소환수 도감·알 뽑기·진화·대량 모델을 만들지 않는다.

협동, 추가 맵, 레이드, 시즌, 거래는 각각 독립적인 다음 범위다. 새 아이디어는 후보로 남기고 현재 마일스톤의 완료 조건을 늘리지 않는다.
